Problem

Troubleshooting 1. AWS S3 이미지 업로드 실패

MultipartFile을 서버 로컬의 File 객체로 변환하는 과정에서 파일 생성에 실패하여 S3 업로드가 진행되지 않았습니다.

Approach

서버 로컬 경로에 의존하는 방식 대신 MultipartFile의 입력 스트림과 파일 메타데이터를 S3 업로드 로직에 전달하도록 개선했습니다.

Action

빈 파일 여부를 검증하고 파일명, Content-Type과 입력 스트림을 S3에 전달했습니다. 업로드 후 반환된 URL을 공연 게시글의 이미지 정보와 연결했습니다.

Result

실행 환경의 로컬 파일 경로에 의존하지 않고 공연 이미지를 S3에 저장할 수 있게 됐습니다.

Problem

Troubleshooting 2. 동일 사용자의 동일 공연 중복 예약 차단

동일 사용자가 같은 공연을 반복 예약하면 예약 인원과 승인·입금 상태의 신뢰성이 깨질 수 있었습니다.

Approach

예약 생성 전에 사용자와 공연의 존재 여부를 확인하고, 동일 사용자의 취소되지 않은 동일 공연 예약이 존재하는지 검증했습니다.

Action

공연 ID와 사용자 ID를 검증한 뒤 사용자별 기존 예약 목록에서 동일 공연의 활성 예약을 확인했습니다. 예약이 존재하면 추가 저장을 중단하도록 구성했습니다.

Result

중복 활성 예약을 차단해 예약 데이터의 정합성을 유지했습니다.

Problem

Troubleshooting 3. CoolSMS 인증번호 재발송 제한

같은 전화번호에서 인증번호를 반복 요청하면 여러 번호가 동시에 유효해지고 불필요한 문자 비용이 발생할 수 있었습니다.

Approach

전화번호별 최신 인증번호를 검증 기준으로 사용하고, 마지막 발송 시각을 기준으로 일정 시간 이내의 재요청을 제한했습니다.

Action

인증번호 발송 전 최근 인증 데이터를 조회하고, 제한 시간이 지나지 않은 요청은 차단했습니다. 검증 요청에서는 최신 인증번호와 입력값 및 만료 여부를 확인했습니다.

Result

최신 인증번호만 유효하게 유지하고 반복 발송을 제한해 인증 흐름의 일관성을 높였습니다.
