Overview

문제, 기여, 결과

Problem집중 중에는 스트레칭 시점을 놓치기 쉽고, 강한 알림은 오히려 사용을 중단하게 만듭니다.

My Contribution알림 간격, 완료 기록, 스트레칭 가이드, 온보딩 흐름을 설계하고 구현했습니다.

Key ChallengeManifest V3의 Service Worker 제약 안에서 알림 예약과 상태 유지를 처리해야 했습니다.

Outcome서버 없이 설치 즉시 사용할 수 있고, 설정과 완료 기록이 브라우저에 유지되는 흐름을 만들었습니다.

Architecture

Manifest V3 기반 Local-first 구조

Popup UI는 React로 구성하고, 알림 예약은 chrome.alarms로 처리했습니다. 사용자 설정과 일일 스트레칭 기록은 Local Storage에 저장해 서버 없이 동작하도록 만들었습니다.

Technical Challenges

기술적 판단

Challenge 01. 알림 피로도 낮추기

Why
건강 알림은 자주 뜨면 유용함보다 방해감이 커져 사용자가 끄게 됩니다.
Decision
즉시 스트레칭, 나중 알림, 알림 On/Off를 분리해 사용자가 직접 강도를 조절하게 했습니다.
Result
작업 흐름을 끊지 않으면서도 스트레칭 행동으로 이어지는 가벼운 흐름을 만들었습니다.

Challenge 02. 상태 유지

Why
확장 프로그램 팝업은 닫히면 UI 상태가 사라지기 때문에 설정과 기록을 별도로 저장해야 합니다.
Decision
알림 설정, 다음 알림 시간, 일일 완료 기록을 Local Storage에 저장했습니다.
Result
브라우저를 다시 열어도 사용자 설정과 당일 진행률이 유지됩니다.

Challenge 03. MV3 Service Worker 제약

Why
Manifest V3 Service Worker는 항상 실행되지 않아 setInterval 방식이 안정적이지 않습니다.
Decision
chrome.alarms API로 반복 알림을 예약하고, 필요한 순간에 상태를 읽도록 구성했습니다.
Result
확장 프로그램 환경에 맞는 알림 트리거를 사용해 단순한 구조를 유지했습니다.

PAAR

알림과 완료 기록의 상태 동기화

Problem알림 On/Off, 완료 기록, 다음 알림 시간이 서로 어긋나면 사용자는 앱을 신뢰하기 어렵습니다.

Action완료 버튼 클릭 시 기록 저장과 다음 알림 예약을 함께 처리하고, Popup UI는 저장된 값을 기준으로 렌더링했습니다.

Alternative메모리 상태만 사용하는 방식은 팝업이 닫힌 뒤 상태가 사라져 장기 사용에 적합하지 않았습니다.

Result서버 없이도 알림 설정과 일일 완료 기록을 유지하는 Local-first 경험을 만들었습니다.
